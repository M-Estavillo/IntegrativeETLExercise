## Design
SIS is authoritative. A left join by integer studentId keeps every SIS student. Multiple LMS courses are stored in courses[]. Accounting is a nested object. This avoids dropping courses or duplicating student details.
Missing LMS data becomes []; missing Accounting data becomes null. Missing individual numeric values also become null rather than zero. Numeric grades become numbers; INC and other nonnumeric grades remain uppercase strings. Names and completion statuses use proper case. Unknown program codes remain uppercase and generate a notice.
Duplicate SIS IDs, Accounting IDs, or LMS student/course combinations cause clear errors instead of silently overwriting data. Unmatched LMS and Accounting records are reported but excluded from the integrated student list.
See data-mapping.md for the complete design.
